# Replit Project Rules

1. GitHub is the single source of truth for source code, documentation, schema definitions, tests, and project state.
2. Always read `PROJECT_STATE.md` before continuing development.
3. Never perform repository-wide analysis unless explicitly necessary.
4. Read only files relevant to the current task.
5. Do not redesign completed architecture without explicit approval.
6. Do not modify unrelated working components or remove working functionality.
7. Never store private keys, seed phrases, API secrets, wallet credentials, or other credentials in source code.
8. Never commit `.env` files or credentials.
9. Real-money autonomous trading remains disabled during development.
10. The Risk Governor remains independent from and higher authority than the Decision Engine.
11. Execution must never bypass the Risk Governor.
12. Generated code is not proof that a task is done; targeted tests and verification are required.
13. Update `PROJECT_STATE.md` whenever task state changes.
14. Update relevant documentation whenever architecture changes; documentation is part of Definition of Done.
15. If credits or resources become insufficient, stop new work and create a continuation checkpoint.
16. Never mark partially completed work as done.
17. Preserve portability between Replit workspaces.
18. Prefer targeted inspection and targeted tests.
19. Avoid unnecessary dependency installation.
20. Do not implement future phases prematurely.
21. `docs/MASTER_BLUEPRINT.md` must not be substantially changed without explicit approval.
