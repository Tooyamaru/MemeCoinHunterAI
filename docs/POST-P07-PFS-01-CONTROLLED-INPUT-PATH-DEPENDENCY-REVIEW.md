## 2. Ordering dependency and evidence of the remaining gap

The Risk/Capital policy snapshot declares `simulation_reference_time` **before** RTI-14; RTI-14's authorization carries the same value and RTI-15 uses it for P07 input. Therefore a preparer could derive PFS's `simulation_reference_time` from the supplied exact snapshot, select an admitted RTI-11 observation explicitly, and invoke PFS **before** OSC. It can compare PFS's original RTI-11 object, selected observation ID/fingerprint, target, state, replay and policy digests with the would-be OSC request. No RTI-12–14 call is required *merely to know the time*. This resolves the previous paper-fact sourcing dependency.

There is a separate dependency for the requested **validated decision/Risk-Capital lineage**:

1. `PaperRiskCapitalPolicySnapshot` requires `context_digest` and `decision_intent_digest` and constrains policy provenance to these and the supplied risk/capital state digests (`core/risk/paper_risk_capital_authorization.py`). These are outputs of RTI-12 and RTI-13 for the chosen RTI-11 result, ruleset and decision time.
2. RTI-14's `_validate_policy` compares the snapshot's two digests with the exact RTI-13 `DecisionIntent` and its context. A mismatch is **`ValueError` validation failure**, not an ordinary Risk/Capital rejection (`backend/application/decision_to_risk_capital_continuation.py`). A matching snapshot can still produce canonical `REJECTED` under the risk/capital authority.
3. `P01Osc01Request.__post_init__` checks snapshot canonical shape, scope candidate/chain/token and decision time against RTI-11. It has **no RTI-12/13 outputs** against which to verify the snapshot's decision/context digests. `OneShotControlledPaperCaller.run` then invokes RTI-12→13→14→15→16 from scratch. It has no supplied-prefix entry point (`backend/application/one_shot_controlled_paper_caller.py`).
4. A focused read-only probe on the current repository created a canonical snapshot with a different but internally self-consistent `decision_intent_digest`, replaced it in an otherwise canonical `P01Osc01Request`, and observed: constructor **accepted**, then `OneShotControlledPaperCaller.run` raised `ValueError: RTI-14 validation failed`. No repository file was modified by this probe. Hence mere `P01Osc01Request` construction cannot attest a complete validated decision/Risk-Capital lineage.

Running RTI-12/13/14 first to obtain and validate the true context/decision/authorization would execute them **again** when the current OSC request is later invoked. Passing an already-produced RTI-13/14 result to a preparer does not fix OSC's mandatory re-execution. Computing those digests in a new adapter, predicting a decision from RTI-11, or silently accepting caller-asserted digests would duplicate ownership or fabricate provenance. Pre-running RTI-15/16 would likewise duplicate the OSC lifecycle. No such shortcut is authorized.

## 3. Boundary if a narrower preparation target is chosen later

An explicitly weaker, **structural-input-only** composition can be specified without architectural change: accept an already canonical RTI-11 result or delegate once to RTI-11 using the exact controller-selected request; stop on non-`COMPOSED`; use the snapshot's explicit `simulation_reference_time` in one PFS request; stop on PFS refusal; construct and return exactly one `P01Osc01Request` without invoking OSC. Its deterministic wrapper digest could bind the invocation ID, exact candidate/pool reference, P02/P03 lineage carried in RTI-11, RTI-11 contract/outcome/digest, selected observation ID/fingerprint and receipt/close times, decision ruleset/time, **unverified** policy snapshot ID/digest, PFS policy/request/result digests, exact PFS products and OSC request input digests. No persistence or full replay claim follows.

Its success would mean only **constructor-valid / ready for an OSC attempt**, not verified decision lineage or prior Risk/Capital approval. Structural identity/time/version mismatch, incomplete P03 pair or tampering stays validation failure. RTI-11 non-`COMPOSED` and PFS bounded refusal propagate exact owner outcomes/reasons with no OSC request; stale source goes through PFS's `MARKET_EVIDENCE_UNAVAILABLE`. A snapshot with the wrong future context/decision digest cannot be safely classified by preparation and may instead cause OSC's RTI-14 `ValueError`; decision terminal outcomes and Risk/Capital `REJECTED` also only become known **inside OSC**. It would be incorrect to label these as preparation-stage bounded rejections or to claim a fully validated approved case.

This narrower contract is **not selected** by this review because the controller requested a complete validated decision/Risk-Capital lineage. No new gate identifier or specification is assigned.
