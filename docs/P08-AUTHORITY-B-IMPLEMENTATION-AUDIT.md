### Criterion 2 — Immutable and deterministic models/results

**Result: PASS**

The implementation uses frozen, slotted dataclasses for facts, edges,
snapshots, graph inputs, projections, and validation results. Nested
representations are frozen with tuples and `MappingProxyType`. Constructor
validation derives or verifies identities and digests without mutation.

Determinism is established by:

- fixed contract and policy versions;
- explicit inputs and explicit comparison snapshots;
- fixed provenance stage order;
- fixed identity projections and domain-separated SHA-256 inputs;
- canonical member ordering;
- fixed failure precedence; and
- terminal-candidate sorting.

No wall-clock, timestamp, timezone, randomness, insertion-order, process
identity, or memory-address input is used.

The focused tests verify replay identity/bytes/digest stability, snapshot
context independence, frozen instances, frozen nested representations, and
immutable graph mappings.

### Criterion 3 — No prohibited ambient or external dependency

**Result: PASS**

`authority_b_lineage.py` imports only standard-library deterministic value and
serialization utilities: dataclasses, enum, hashlib, json, regular
expressions, immutable mapping support, typing, and Unicode normalization.

There is no clock, random, environment, filesystem, database, cache, network,
provider, RPC, wallet, signer, execution, API, persistence, or T07-internal
dependency. The focused dependency-boundary test checks the public module for
prohibited ambient modules and prohibited authority operations. Static review
confirmed that no such dependency is present.

### Criterion 4 — Canonical serialization, identity, digest, and null rules

**Result: PASS**

The implementation matches the approved profile:

- canonical compact UTF-8 JSON with no BOM;
- NFC normalization before escaping;
- unpaired-surrogate rejection;
- Unicode code-point key ordering;
- preserved array order;
- exact quote and reverse-solidus escaping;
- unescaped solidus;
- required short control escapes and lowercase `\u00xx` escapes;
- direct non-ASCII UTF-8;
- lowercase boolean and null tokens;
- rejection of semantic nulls and numeric tokens in Authority B values;
- exact six-element fact/edge identity projection;
- domain-separated SHA-256 fact and edge identities;
- edge digest over the complete edge representation excluding only
  `edge_digest`; and
- snapshot identity/digest rules with snapshot values excluded from fact and
  edge identity.

The focused tests cover the required escaping, NFC behavior, surrogate/null/
numeric rejection, exact identity derivation, digest non-circularity, and
canonical ordering.

### Criterion 5 — Explicit snapshot duplicate comparison

**Result: PASS**

Duplicate comparison occurs only after the candidate identity is computed and
only against the explicitly supplied immutable
`AuthoritativeLineageFactSetSnapshot`.

The implementation provides the required outcomes:

- no matching identity: accepted as a new candidate;
- byte-identical matching fact: `EXACT_DUPLICATE`, idempotent projection reuse;
- same identity with different canonical bytes:
  `CONFLICTING_DUPLICATE`, fail closed;
- multiple matches: `DETERMINISM_FAILURE`; and
- identity/digest disagreement: fail closed.

No registry, database, filesystem, cache, provider, network, insertion order,
last-write-wins rule, or caller preference is consulted. Snapshot context does
not participate in fact or edge identity.

### Criterion 6 — Deterministic graph validation and fail-closed behavior

**Result: PASS**

The graph boundary validates explicit lifecycle-scoped result identities and
lineage facts. It deterministically handles:

- correction and supersession edges;
- valid multi-hop chains;
- direct branching;
- unsupported merge/convergence;
- cycles;
- self-reference;
- missing or orphan endpoints;
- cross-lifecycle references;
- contradictory facts;
- invalid provenance and identity/digest state;
- duplicate/conflicting duplicate state; and
- zero or multiple terminal candidates.

The implementation uses the exact approved failure precedence:

`MALFORMED_FACT` → `INVALID_IDENTITY` → `INVALID_LIFECYCLE` →
`MISSING_ENDPOINT` → `CROSS_LIFECYCLE_REFERENCE` →
`CONFLICTING_DUPLICATE` → `LINEAGE_SELF_REFERENCE` →
`LINEAGE_CYCLE` → `MERGE_UNSUPPORTED` →
`LINEAGE_BRANCH_CONFLICT` → `CONTRADICTORY_LINEAGE` →
`PROVENANCE_FAILURE` → `DETERMINISM_FAILURE` → `DIGEST_FAILURE`.

No branch, merge, cycle, missing endpoint, or ambiguous terminal is repaired or
selected. A structural terminal candidate is returned only as an intermediate
candidate for T07 validation.

The focused tests cover a valid mixed correction/supersession chain and the
required branch, merge, cycle, self-reference, missing-endpoint,
cross-lifecycle, contradiction, and ambiguous-terminal failures.

### Criterion 7 — Exact correction/supersession mapping into T07

**Result: PASS**

`T07LineageProjection.from_edge` maps:

- `correction` only to `correction_lineage`; and
- `supersession` only to `supersession_lineage`.

The projection carries the canonical edge representation without redefining
T07's contract version, evaluator version, status, failure reason, G2/G3/G4
fields, result digest, classification digest, or canonical-head authority.

The implementation provides the approved exhaustive Authority B to T07
failure-reason mapping, including:

- malformed/identity/missing-endpoint failures to
  `MISSING_REQUIRED_INPUT`;
- lifecycle, cross-lifecycle, duplicate, graph-conflict, and contradiction
  failures to `CONFLICTING_INPUT`;
- merge and determinism failures to `UNRESOLVED_RESIDUAL`;
- provenance failure to `PROVENANCE_LINKAGE_FAILURE`; and
- digest failure to `DIGEST_FAILURE`.

Focused tests verify both destination fields, exclusive destination
selection, exact duplicate reuse, and conflict mapping. No T07 source or test
file was changed.
