## 2. Contract that the research must preserve

For frozen UTC reference R and minute cutoff C, the only candle starts are C-180, C-120 and C-60 seconds. Each row is factual, unique, integral, contiguous at 60 seconds, closed, fresh under the original policy, and bound to the original Solana pool/program/base/quote/token tuple. Token equals the original base mint. Original start and source/receipt clocks remain distinct.

All trade and quote-source inputs determining the historical values must satisfy the parent's before-C source-availability requirement. An event-time filter alone is insufficient. Provider identity, schema/query/model versions, raw response digest and exact public bindings remain visible. No deduplication, filling, interpolation, inversion, USD relabeling, provider substitution or arbitrary success callback can create admissible facts.

The proposed candle incidence remains **one physical read-only request, 32,768 request bytes, 1,048,576 response bytes and 10 seconds total**, subject to any lower caller limit. Retry, redirect, fallback, pagination, polling and token refresh remain zero. Neither this research nor an offline fixture is operational qualification. Client rejection on timeout does not prove provider execution time or absence of billing.

## 4. Interval resolution: a lossless representation mapping

E2 defines raw End as Start + Duration - 1 second. For a valid original 60-second row:

| Field | Required value |
| --- | --- |
| Original Start | Integral UTC second, aligned to 60 seconds |
| Original Duration | 60 seconds |
| Original raw End | Start + 59 seconds |
| Canonical exclusive end | raw End + 1 second = Start + 60 seconds |

Retain original Start/End/Duration unchanged and record the mapping/profile in provenance. Reject an inconsistent raw End, duration, units, alignment or unpinned field representation. The mapping changes no OHLC value, observation start, order, uniqueness, 60-second spacing, receipt time, freshness or cutoff. It does not convert an open candle into a closed one.

**Conclusion:** the inclusive/exclusive distinction is not a semantic incompatibility once its typed source representation is pinned. The controller's new offline authority permits specification of this mapping. No runtime mapper is implemented, and full schema/output typing plus all other source gates remain open. This resolves the documentary representation dependency without relaxing acceptance.

## 6. Why conservative offline engineering cannot close this gate

Consider two possible source histories with the same event timestamps, returned pool/mint identities, three OHLC rows and raw response bytes. In one, all determining trades/quotes were available before C. In the other, a pre-C trade arrived late or its USD conversion was computed from post-C information. A client receiving the same bytes after C cannot distinguish them from candle timestamps, volume or hashes. Only source-maintained as-of/input-clock evidence, or a complete independently retained before-C capture with its own approved authority, distinguishes the histories.

This is an inference from the required information and inspected response contracts, not a claim that a provider actually behaved like the second history. It proves why an affirmative offline fixture, receipt timestamp or caller Boolean cannot satisfy the missing predicate. Similarly, exactly three returned rows prove visible count, not complete source ingestion. Sparse/no-fill and a four-row overflow sentinel solve different problems.

Safe conservative outcomes remain `CAPABILITY_UNVERIFIED` with `SCHEMA_NOT_PINNED`, `USD_CUTOFF_SEMANTICS_UNPROVEN` and/or `COMPLETENESS_UNPROVEN`. No observations, signal or diagnostic can be emitted. Building an always-stopped adapter/seam without a credible admissible source profile adds an unused owner without advancing the objective, so no runtime implementation is justified in this batch. Existing CoinGecko V1 code, serialization, hashes and fail-closed behavior remain unchanged.

### Exact external evidence needed next

The smallest gate is **one authoritative supported profile/evidence bundle**, preferably for the existing conditional Bitquery Pairs candidate, answering:

1. **Pinnable profile:** supply the complete output SDL/types/nullability/precision and exact supported absolute-window operation; bind schema/model revisions or specify version-change rejection. Resolve original CPMM pool/program/mint/orientation without aliasing. The raw inclusive-end mapping in §4 is already resolved and does not need another engineering approval.

Prove post-C facts cannot determine the admitted window; do not answer only that trade timestamps are below C.
3. **Complete bounded retrieval:** establish one-operation completeness for the exact window/dimensions, explicit partial-index/truncation signaling and four-row-sentinel behavior, plus the relevant intended plan/entitlement and bounded charging rules. Client byte/deadline ceilings remain unchanged and later require measurement.

An official publication or supplied vendor-supported schema/contract can close documentary questions without exposing credentials. Vendor contact is not performed or authorized by this batch. An account response or successful bounded latency test alone cannot prove private historical construction semantics. If a provider has no such as-of evidence, the remaining alternative is a separately governed complete before-C trade/quote capture with explicit capture/finality/source authority and new budget; no polling, stream, account or economic action is opened here.

Operational access is therefore **not yet the sole gate**. No runnable query, exact target, account qualification or command is fabricated.
