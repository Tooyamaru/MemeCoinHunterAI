# P07-PFS-01 — Bounded Simulation-Only Paper Fact Sourcing

**Status:** SPECIFICATION COMPLETE / READY FOR CONTROLLER REVIEW / IMPLEMENTATION NOT AUTHORIZED

**Proposed contract:** `p07-pfs-01-v1`

**Selection:** Controller selected separate simulation-only fact sourcing after the bounded post-OSP dependency decision on GitHub `main` `71e7b3f32e4b8c7fff8290abc32cdc3e946cf1c7` (PR #52, CI #156 PASS). This is a P07 input-sourcing dependency for a *later* supervised controlled-input path, not an RTI continuation or an OSC caller.

## 1. Owner audit and architectural choice

| Existing owner | Exact responsibility | PFS-01 relationship |
| --- | --- | --- |
| P02/P04-LME and RTI-11 | Admit historical source observations and one controller-selected pool; compose signal/opportunity | Consume an **already-produced** canonical RTI-11 result with exact admitted historical price observation, pool identity and source provenance. No diagnostic/provider call or opportunity rerun. |
| P07-T01 / RTI-15 | Validate and materialize `PaperSimulationInput` from approved Risk/Capital and explicit caller facts | Do not create admission, approval or a P07 input. PFS may prepare a matching `InitialPaperStateIdentity`; RTI-15 remains its later consumer. |
| `PaperFillInstruction`, `FrictionComponents` | Canonical caller input shape and friction evidence | Construct exactly once from independently specified assumptions and observed proxy; use existing constructors and digests. They do **not** source market or fill evidence. |
| `PaperLifecycleEvidence`, `PaperPositionExposureState`, `ValuationObservation`, `AccountingContext`, `PaperReconciliationExpectation` | Canonical input/state/evidence shapes | Construct once from explicitly versioned simulation assumptions and source facts; preserve these constructors' validation ownership. |
| P07-T02/T03/T04/T05, RTI-02/16, OSC-01 | Fill outcome, state transition, ledger, independent expectation comparison, lifecycle composition and caller delegation | **Never invoke.** PFS does not decide fill status, create an actual ledger/next state, compute reconciliation `MATCH`, or run OSC. |

The selected design is **(b)**: PFS-01 owns bounded *simulation assumption and source-to-input derivation*, and materializes its output through the existing canonical input constructors. Its successful result retains the **exact two constructed canonical objects** for a later OSC-ready request, plus the matched initial paper state identity. The constructors own their own validation; PFS owns only new policy/provenance/linkage checks. No new fill, transition, ledger, reconciliation, Risk/Capital, or execution domain owner is created. A bare facts-only output that leaves construction of both objects to the controller would not resolve the documented input-sourcing dependency.

## 2. Closed input and assumption boundary

One HTTP-independent, stateless operation, provisionally `PaperFactSourcingService.source(request: PaperFactSourcingRequest) -> PaperFactSourcingResult`, accepts **one explicit canonical request**. No environment, clock, secret, provider, database, scheduler, or global state is an input. Its fields are:

1. Exact canonical `P01Rti11CompositionResult` at `p01-rti-11-v1`, including selected `candidate_id`, exact `ExactPoolDiagnosticTarget` with its caller-owned reference, source diagnostic and admitted P02-T09 `PRICE` observations. Only `COMPOSED` may yield paper objects. The controller selected/approved the candidate and pool **before** RTI-11; PFS cannot select/rank or fetch another.
2. Exact canonical `ExecutionObservation`, `SimulationConfigurationIdentity`, `InitialPaperStateIdentity` when using an existing state, and `ReplayIdentity`, all supplied before OSC. Existing versions and paper-only meaning remain authoritative. Neither `ExecutionObservation.quality == PASS` nor its quote/liquidity digest alone proves a real executable quote. For a fresh genesis state, PFS constructs a matching `InitialPaperStateIdentity` from explicit genesis assumptions; it must not pretend to have found a historical state.
3. Explicit timezone-aware `simulation_reference_time`, `paper_evaluation_time` and chosen source observation identity/digest. Exactly one accepted, positive, finite, closed-minute USD price observation from the RTI-11 nested diagnostic is selected by identity. The observed candle is only a **historical valuation/reference-price proxy**; its source observation timestamp, receipt/availability time, request cutoff, selected pool and currency remain distinct.
4. Exact immutable `PaperSimulationAssumptionPolicy` with explicit ID/version, simulation mode (`FRESH_GENESIS` or `EXISTING_EXPLICIT_STATE`), order side, requested quantity or a stated notional-to-quantity rule, quantity/price/fee units, quote currency, a fixed `OBSERVED_CLOSE_PROXY` reference-price rule, simulated fill-time rule or explicit simulated fill time, all seven absolute `FrictionComponents` (including explicitly zero values), finite positive simulated capacity, partial-fill permission, explicit valuation-age limit, absolute accounting fee/priority-fee rules, and independent reconciliation comparison-field policy. Include explicit stream identity, positive sequence, predecessor digest (or explicit genesis absence), expectation identity, and policy provenance. No optional numeric field silently defaults to zero.
5. For `FRESH_GENESIS`: explicit new state ID/version, portfolio scope, target asset identity, as-of time and explicit zero target position/zero cost basis declaration. The service constructs the corresponding zero `PaperPositionState`, `PaperExposureState` and `PaperPositionExposureState` with simulation provenance and derives a matching `InitialPaperStateIdentity` using a versioned canonical position/exposure projection. **No balance or historic holdings are asserted or invented.** A genesis state must have sequence one and no previous ledger digest; a non-genesis prior stream must not be reset to genesis.
6. For `EXISTING_EXPLICIT_STATE`: one exact canonical `PaperPositionExposureState`, exact `InitialPaperStateIdentity`, and explicit prior stream/sequence reference. Their state ID/version, portfolio scope, as-of time, target position, projection digests and provenance must match. PFS never searches storage, infers a missing prior holding, or promotes a stored RTI-03 snapshot into a live prior state. For SELL, available inventory is the exact target position quantity when its quality is canonical; insufficient/unknown inventory is not repaired.

Policy ID/version, RTI-11 source contract/digest, P02 observation digest and source times, selected pool reference, replay ID, execution observation digest, state identity and state digest, and explicit reference/evaluation times are mandatory provenance. `SimulationConfigurationIdentity`'s declared fill/friction model versions must be consistent with the policy and existing P07 versions, with no alias, “latest” or fallback. Policy or input changes change the result digest.

## 3. Field-level fact classification

| Destination | Observed market fact | Explicit simulation assumption | Deterministically derived paper input | Never claimed |
| --- | --- | --- | --- | --- |
| `PaperFillInstruction.side`, quantity/units | None | Order side, base quantity or notional rule, units | Exact requested quantity, with finite Decimal and explicit rounding rule | Actual order or trade intent authorization |
| `reference_quote_price`, `quote_observation_time` | Selected closed-candle USD **close**, candle start, close boundary and receipt provenance | `OBSERVED_CLOSE_PROXY` policy and currency/age cutoff | Price proxy = exact accepted close; quote observation time = verified minute close, only if source was received by simulated fill/reference time | Executable quote, on-chain pool execution price, venue liquidity |
| `executable_liquidity`, `fill_time`, `available_inventory` | No executable-liquidity or fill-time evidence in OHLCV | Positive **simulated capacity** and explicit timing rule; genesis/existing state mode | Capacity copied with assumption marker; simulated fill time from rule; SELL inventory from the exact prior state | Real capacity, real fill detection, transaction inclusion |
| `friction`, fees | None for realized effects | All absolute fee, spread, slippage, impact, drift, priority-fee and MEV offsets, each explicitly supplied/versioned | Exact `FrictionComponents` with non-empty evidence mapping identifying simulation policy/source; corresponding accounting fee amounts in quote units | Realized slippage, paid fee, priority fee, MEV |
| `PaperLifecycleEvidence.prior_state`, target, valuation | Historical price proxy only for valuation; no holdings | Explicit genesis-zero declaration **or** existing canonical prior state; valuation max age, asset/unit scope | Canonical prior paper state and `ValuationObservation`/`ValuationContext` with source observation and receipt timestamps; target identity linked to execution observation | Historic portfolio, wallet balances, cash funding, market-to-market realized P&L |
| `accounting_context`, reference time | No settlement/accounting receipt | Absolute hypothetical fee model and explicit simulation timeline | `AccountingContext` labelled simulation-only and consistent with `FrictionComponents` and cost-basis unit; lifecycle reference at explicit paper time | Settled accounting or external cash movement |
| `ledger_stream_identity`, sequence, predecessor | None | Explicit stream/sequence; genesis absence or exact pre-existing prior digest | Passed unchanged, with state/replay binding | Durable stream ownership or unseen history |
| `reconciliation_expectation` | No observed external ledger | **Precommitted** expectation identity, replay ID and policy comparing known sequence, replay, prior state and reference time | Canonical `PaperReconciliationExpectation` constructed **before** any P07-T04 ledger from independently known policy facts; no predicted entry/outcome digest | External reconciliation, economic settlement, guaranteed `MATCH` |

P07-T02 alone later computes hypothetical `PaperFillOutcome` and effective price; P07-T03 alone computes next state/accounting effects; P07-T04 alone constructs the ledger; P07-T05 alone compares the precommitted expectation. PFS must never pre-run these owners to fill an expectation. An `AVAILABLE` expectation means only that a **precommitted simulation comparison** is available, with no external-observation timestamps asserted. If it cannot be precommitted independently, use a bounded `EXPECTATION_UNAVAILABLE` stop, never a synthetic ledger-derived expectation. A later `MATCH` means internal consistency under that policy only.

## 4. Feasibility, temporal and identity rules

- Validate exact types, versions, digest reconstructions and frozen canonical material before producing a paper object. Reject tampering, mismatched candidate/token/pool/asset, unsupported units or currency, missing policy components, non-finite/negative assumptions, conflicting state identities, replay/stream reuse, future or stale evidence, contradictory cutoff/receipt/fill timing, and prior-state/projection mismatch as standardized `ValueError` when structurally invalid. Ordinary evidence insufficiency or a declared missing assumption produces a closed refusal without paper objects.
- Require the selected accepted source observation to belong to the RTI-11 result's **exact** candidate, chain, token and pool and to be available by the explicit simulated fill and lifecycle reference times. Minute close time is the observation's minute-start plus exactly 60 seconds; source receipt/availability must be at or after that close boundary. Require strictly positive finite USD close and explicit max-age policy. Do not recast USD as the pool's quote mint or use OHLCV volume as executable depth.
- `paper_evaluation_time`/lifecycle reference and simulated fill time must be explicit UTC-normalized instants and comply with source availability, `prior_state.as_of_time`, RTI-11 reference and anticipated `PaperSimulationInput.simulation_reference_time` constraints. `PaperFillInstruction.fill_time` cannot be inferred from the wall clock. PFS can validate the anticipated simulation reference but cannot force RTI-14/15 to produce it; the later controlled-input composition must reject a mismatch before OSC.
- Require simulated capacity to be a positive, explicitly supplied finite Decimal and marked as an assumption. Missing capacity, missing price/availability, or inadequate source evidence is a refusal. If capacity is below requested quantity, only an explicit partial-fill policy may pass that assumption to P07-T02; otherwise refuse. This does **not** claim real fill feasibility. A hypothetical P07-T02 `FAILED`, `REJECTED`, `UNAVAILABLE` or `PARTIALLY_FILLED` remains the P07 owner's outcome.
- For fresh genesis, construct exactly one zero target position in the stated asset/portfolio and matching exposure at the accepted valuation proxy. Define position and exposure projection digests as SHA-256 of their existing canonical representations under a versioned PFS projection rule; construct `InitialPaperStateIdentity` with those exact digests and simulated provenance. For existing state, validate the same projections against caller-provided initial identity. Never claim that RTI-03 readback can reconstruct the prior state or that a new genesis represents historical inventory. No modeled cash balance bypasses independent Risk/Capital authorization.
- Accounting fees are the exact policy absolute amounts, in the same quote/cost-basis unit and with a declared simulation observation time at or before lifecycle reference; `AccountingContext` provenance must state assumption, not receipt. Valuation provenance must bind accepted source ID/digest, close timestamp, actual receipt, selected pool and proxy-policy version. Different evidence timing or source selection changes output digests.
- Precommit expectation **only** from known stream sequence, replay ID, prior state digest and reference-time fields, with `expected_presence=true`. Do not include `entry_id`, `event_identity_digest`, `entry_digest`, realized fill status, resulting-state digest or `expected_canonical` unless independently supplied and validated *before* lifecycle invocation. No agreement on these fields may be manufactured by running P07-T02–T04 first.

## 5. Result, outcomes, cardinality and STOP

Immutable `PaperFactSourcingResult` includes exact request/upstream/policy and their versions/digests, one closed outcome, finite safe reasons, optional **exact** `PaperFillInstruction`, `PaperLifecycleEvidence` and matching `InitialPaperStateIdentity`, source observation digest, and a deterministic SHA-256 result digest. Only `FACTS_MATERIALIZED` contains all three canonical products; all refusal/unavailable outcomes contain none. Proposed closed non-success outcomes: `UPSTREAM_NOT_COMPOSED`, `MARKET_EVIDENCE_UNAVAILABLE`, `CAPACITY_UNAVAILABLE`, `PRIOR_STATE_UNAVAILABLE`, `EXPECTATION_UNAVAILABLE`, and `SOURCING_UNAVAILABLE` for unexpected internal failure or invalid constructor output. Malformed/tampered inputs, identity/time/structural/version mismatches, and canonical constructor `ValueError` remain standardized validation failures, not ordinary refusals. Cancellation propagates. No exception text or secret is returned.

Result digest binds PFS contract/outcome/reasons, RTI-11 contract/outcome/result digest, exact selected source observation identity/digest and available/observed times, candidate/pool reference, full explicit policy canonical material/digest, execution/configuration/replay/initial-state identity material, supplied or generated prior state digest, and all three output contract/digests or explicit absence. No wall clock, environment, provider call identity, database state or mutable shared history enters the digest. Equal canonical inputs and owner constructors produce equal outputs/digests. `PaperFillInstruction` itself has no general source field: the **in-memory PFS wrapper and nested friction/valuation/accounting provenance** retain the policy/source links; RTI-03 persistence does not thereby become a full PFS/OSC replay archive.

Within a call: zero P02/P03/P04-LME/RTI-11 provider/producer or P07-T01–T07/RTI-02/15/16/OSC invocations; at most one selected observation and at most one materialization of each canonical input record (and its nested genesis/valuation/accounting/expectation records) after validation. No loop, retry, second candidate/pool, substitute price, or fallback policy. Hard STOP is the **exact pair of canonical paper input objects plus linked initial identity**, wrapped in PFS result, entirely in memory. A later controlled-input-path gate may use those exact objects and separately decide when to invoke OSC; PFS never runs OSC/OSP/RTI-04 or persists anything.

## 6. Verification criteria and governance

Future implementation, if separately authorized, requires focused tests for exact canonical source/pool membership, closed-candle/receipt/freshness and USD-unit checks; explicit all-component friction/capacity/partial-fill assumptions; fresh genesis versus explicit existing prior state and identity projections; SELL inventory; independent expectation built without P07-T02–T04 calls; one-time construction of the exact canonical objects; deterministic digest and provenance; every bounded refusal; validation and cancellation; and zero OSC/RTI/owner/provider delegation. Tests must prove that changing a source/policy/state digest changes the PFS result and that OHLCV alone cannot produce a favorable fill claim.

This specification authorizes **no runtime/source implementation** or controlled-input-path implementation. No provider polling, autonomous selection, scheduler/worker/queue, API/dashboard, persistence/full replay, P08 evaluation wiring, wallet/signing/RPC/DEX, transaction construction/broadcast, real fill detection, economic realization, or live trading. G2 remains BLOCKED / UNRESOLVED / NOT AUTHORIZED; G3/G4/P09 remain NOT AUTHORIZED.
